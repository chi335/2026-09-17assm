## 📌 1. 기본 언어 요소 (Basic Language Elements)

### (1) 명령어(Instruction) vs 지시자(Directive)
* **Instruction (명령어)**: CPU가 실제 실행하는 행동 지침입니다 (예: `MOV`, `ADD`, `SUB`, `NOP` 등).
* **Directive (지시자)**: 어셈블러(Assembler)에게 프로그램 구조나 메모리 할당 방식을 안내하는 지시서입니다 (예: `.data`, `.code`, `PROC`, `ENDP` 등).

### (2) 리터럴 (Literals)
* **정수 리터럴 (Integer Literals)**: 숫자 뒤에 진법 접미사(Radix)를 붙여 표현합니다.
  * `26` / `26d` : 10진수
  * `11010011b` : 2진수
  * `42q` / `42o` : 8진수
  * `1Ah` / `0A3h` : 16진수 (첫 글자가 문자인 경우 맨 앞에 `0`을 붙여 식별자와 구분)
* **실수 리터럴 (Real Number Literals)**: IEEE 754 부동소수점 표준 방식을 사용합니다.
  * 32비트 float 기준: **부호 비트($S$, 1bit)** + **지수부($E$, 8bit)** + **가수부($M$, 23bit)**
* **문자 및 문자열 리터럴**: 홑따옴표(`'`) 또는 쌍따옴표(`"`)를 사용해 정의하며, 문자열 끝에는 `0` (NUL)을 붙여 마감하기도 합니다.

### (3) 상수 정수식 (Constant Integer Expressions)
* **연산자 우선순위**: `( )` (1순위) $\rightarrow$ Unary `+`, `-` (2순위) $\rightarrow$ `*`, `/`, `MOD` (3순위) $\rightarrow$ `+`, `-` (4순위)

### (4) 식별자 (Identifiers) 및 예약어 (Reserved Words)
* **식별자 규칙**: 대소문자를 구분하지 않으며, 1~247자 길이를 가집니다. 첫 글자는 영문자, `_`, `@`, `?`, `$`만 가능합니다.
* **예약어**: 레지스터 이름, 명령어 이름(MOV, ADD 등), 지시자, 데이터 타입(BYTE, WORD 등)은 식별자로 사용할 수 없습니다.

### (5) 주석 (Comments) & NOP
* **한 줄 주석**: 세미콜론(`;`) 사용.
* **블록 주석**: `COMMENT ! ... !` 또는 `COMMENT & ... &` 사용.
* **NOP (No Operation)**: 1바이트 크기의 명령어로, 아무 작업도 수행하지 않지만 메모리 주소 정렬(Alignment)을 통해 연산 속도를 최적화할 때 사용됩니다.

## 🛠️ 2. 어셈블리 프로그램의 기본 구조 및 예제

```assembly
.data
    sum DWORD 0           ; 32비트 변수 sum 선언 및 0으로 초기화

.code
main PROC
    mov eax, 5            ; EAX 레지스터에 5 대입
    add eax, 6            ; EAX 레지스터에 6을 더함 (EAX = 11)
    mov sum, eax          ; 결과를 sum 변수에 저장
    
    INVOKE ExitProcess, 0 ; 프로그램 종료 (운영체제로 제어 반환)
main ENDP
END main
```

### 📂 세그먼트 구조 (Segment Structure)

| 세그먼트 | 영역 설명 |
| :--- | :--- |
| **`.data`** | 변수가 위치하는 데이터 영역 |
| **`.code`** | 실행 가능한 명령어가 위치하는 코드 영역 |
| **`.stack`** | 런타임 스택 영역 |

## 🔄 3. 어셈블, 링크 및 실행 (Assemble-Link-Execute Cycle)

1. **Source File (`.asm`)**: 어셈블리 언어로 작성된 소스 코드
2. **Assembler (MASM)**: 소스 코드를 기계어 오브젝트 파일(`.obj`)로 변환하고 리스팅 파일(`.lst`) 생성 가능
3. **Linker**: 오브젝트 파일과 라이브러리를 결합하여 최종 실행 파일(`.exe`) 생성

## 📊 4. 데이터 정의 (Defining Data)

### (1) 주요 내장 데이터 타입 (Intrinsic Data Types)

| 데이터 타입 | 크기 | 설명 |
| :--- | :--- | :--- |
| **BYTE / SBYTE** | 8비트 (1바이트) | 부호 없는 / 부호 있는 8비트 정수 |
| **WORD / SWORD** | 16비트 (2바이트) | 부호 없는 / 부호 있는 16비트 정수 |
| **DWORD / SDWORD** | 32비트 (4바이트) | 부호 없는 / 부호 있는 32비트 정수 |
| **QWORD** | 64비트 (8바이트) | 64비트 정수 |
| **TBYTE** | 80비트 (10바이트) | Packed BCD 정수 |
| **REAL4 / REAL8 / REAL10** | 4 / 8 / 10바이트 | 단정밀도 / 배정밀도 / 확장정밀도 부동소수점 |

### (2) 배열 및 공간 할당 (`DUP` 연산자)
* 반복되는 데이터 할당 시 `DUP` 연산자를 사용합니다.
  * `BYTE 20 DUP(0)` : 0으로 초기화된 20바이트 공간
  * `BYTE 20 DUP(?)` : 초기화되지 않은 20바이트 공간

### (3) 미초기화 데이터 영역 (`.DATA?`)
* 초기화되지 않은 대용량 변수 선언 시 `.DATA?` 세그먼트를 사용하면 실행 파일(`.exe`)의 크기를 획기적으로 줄일 수 있습니다.

### (4) 엔디안 (Endianness)
* **Little-Endian (리틀 엔디안)**: Intel x86 계열 CPU에서 사용하며, **하위 바이트(LSB)를 낮은 메모리 주소**에 저장합니다. (산술 연산 최적화)
* **Big-Endian (빅 엔디안)**: 상위 바이트(MSB)를 낮은 메모리 주소에 저장합니다. (네트워크 전송 표준)

## 🔑 5. 기호 상수 (Symbolic Constants)

상수 이름에 값을 바인딩하여 코드의 가독성과 유지보수성을 높입니다.

### (1) 등호 지시자 (`=`)
* 정수 표현식과 상수를 연결하며, 코드 중간에 **재정의(Redefinition)가 가능**합니다.
* 현재 위치 카운터(`$`)를 활용하여 배열이나 문자열의 크기를 자동으로 계산할 수 있습니다.

```assembly
list BYTE 10, 20, 30, 40
ListSize = ($ - list)        ; ListSize = 4
```

### (2) `EQU` 지시자
* 정수 식, 기호, 텍스트 등을 상수에 바인딩하며, **재정의가 불가능**합니다.

```assembly
PI EQU <3.1416>
pressKey EQU <"Press any key to continue...", 0>
```

### (3) `TEXTEQU` 지시자
* 텍스트 매크로를 생성하여 코드 표현을 치환할 수 있습니다.

```assembly
move TEXTEQU <mov>
setupAL TEXTEQU <move al, 10>
```

## 🔢 6. 정수 및 실수 표현법 (2's Complement & Bias)

---

### (1) 2의 보수 (2's Complement)

부호 있는 정수(Signed Integer)를 컴퓨터 내부에서 표현하고 연산하기 위해 사용되는 표준 방식입니다.

* **변환 과정**:
  1. **1의 보수 구하기**: 모든 비트를 반전합니다 ($0 \rightarrow 1$, $1 \rightarrow 0$).
  2. **1 더하기**: 1의 보수 결과에 $1$을 더합니다.

* **예시 (+5를 -5로 변환하기)**:
  * $+5$ (8비트 2진수): `0000 0101`
  * 1의 보수 (비트 반전): `1111 1010`
  * 2의 보수 ($+1$ 연산): `1111 1011` ($\rightarrow -5$)

* **주요 특징**:
  * **MSB (Most Significant Bit, 최상위 비트)**: 부호 비트 역할을 수행합니다. (`0` = 양수 / `1` = 음수)
  * **$0$의 유일성**: $+0$과 $-0$의 구분이 없고 `0000 0000` 하나로 유일하게 표현됩니다.
  * **연산의 단순화**: 별도의 감산기(Subtractor) 없이 가산기(Adder) 하나만으로 뺄셈 연산($A - B = A + (-B)$)을 수행할 수 있습니다.

---

### (2) 바이어스 표현법 (Bias / Biased Representation)

IEEE 754 부동소수점(Floating Point)의 **지수부(Exponent)** 영역에서 음수/양수 지수를 부호 비트 없이 정수로 표현하고 비교하기 위해 사용하는 방식입니다.

* **기본 개념**: 실제 지수값에 일정 상수값(**Bias**)을 더해 항상 양수로 만들어 저장합니다.
* **공식**:
  $$\text{저장되는 지수(Biased Exponent)} = \text{실제 지수(Actual Exponent)} + \text{Bias}$$
* **Bias 계산 공식**:
  $$\text{Bias} = 2^{k-1} - 1 \quad (k = \text{지수부 비트 수})$$

| 정밀도 종류 | 지수부 비트 수($k$) | Bias 값 | 지수 저장 범위 (실제 지수) |
| :--- | :--- | :--- | :--- |
| **단정밀도 (REAL4 / 32-bit)** | 8 bit | **$127$** ($2^{7}-1$) | $-126 \sim +127$ |
| **배정밀도 (REAL8 / 64-bit)** | 11 bit | **$1023$** ($2^{10}-1$) | $-1022 \sim +1023$ |

* **예시 (32비트 float, Bias = 127 기준)**:
  * 실제 지수가 $+3$ 인 경우: $3 + 127 = 130 \rightarrow 10000010_2$ 로 지수부에 저장
  * 실제 지수가 $-3$ 인 경우: $-3 + 127 = 124 \rightarrow 01111100_2$ 로 지수부에 저장

* **장점**: 지수부의 크기를 비교할 때 부호 판단 없이 **부호 없는 정수(Unsigned Integer) 크기 비교 연산**만으로 빠르고 쉽게 지수 크기를 정렬할 수 있습니다.

## ⚙️ 7. x86 프로세서 주요 레지스터 (Registers)

> 32비트 IA-32의 **기본 프로그램 실행 레지스터 16개**와 **64비트(x86-64) 확장 레지스터** 핵심 요약입니다.

---

### 1. 32비트 기본 프로그램 실행 레지스터 (16개)

32비트(IA-32) 환경에서는 **범용 레지스터 8개 + 세그먼트 레지스터 6개 + EFLAGS + EIP = 총 16개**의 핵심 레지스터로 구성됩니다.

```
┌─────────────────────────────────────────────────────────────┐
│              32-Bit Basic Execution Registers               │
├──────────────────────────────────┬──────────────────────────┤
│ 범용 레지스터 (8개)              │ 세그먼트 레지스터 (6개)  │
│ EAX, EBX, ECX, EDX               │ CS, DS, SS               │
│ ESI, EDI, EBP, ESP               │ ES, FS, GS               │
├──────────────────────────────────┴──────────────────────────┤
│ 상태 및 제어 레지스터 (2개)                                  │
│ EFLAGS (Status Flags)  /  EIP (Instruction Pointer)         │
└─────────────────────────────────────────────────────────────┘
```

#### ① 범용 레지스터 (8개)
각 32비트 레지스터는 하위 16비트 및 8비트(`H`: High / `L`: Low) 단위로 분할하여 액세스할 수 있습니다 (호환성 유지).

| 32비트 | 16비트 | 8비트 (High / Low) | 주요 역할 및 특징 |
| :--- | :--- | :--- | :--- |
| **EAX** | AX | AH / AL | **누산기 (Accumulator)**: 산술/논리 연산, 곱셈/나눗셈, **함수 반환값 저장** |
| **EBX** | BX | BH / BL | **베이스 레지스터 (Base)**: 메모리 주소 지정 시 베이스 포인터 역할 |
| **ECX** | CX | CH / CL | **카운터 레지스터 (Count)**: 반복문(`LOOP` 명령어)의 카운터 역할 |
| **EDX** | DX | DH / DL | **데이터 레지스터 (Data)**: I/O 포트 주소 지정, 곱셈/나눗셈 연산 보조 |
| **ESI** | SI | - | **소스 인덱스 (Source Index)**: 메모리 복사 및 문자열 처리 시 원본 주소 |
| **EDI** | DI | - | **목적지 인덱스 (Destination Index)**: 메모리 복사 및 문자열 처리 시 목적지 주소 |
| **EBP** | BP | - | **베이스 포인터 (Base Pointer)**: 스택 프레임 기준 주소 (매개변수/지역변수 참조) |
| **ESP** | SP | - | **스택 포인터 (Stack Pointer)**: 현재 스택의 최상단(Top) 메모리 주소 가리킴 |

---

#### ② 세그먼트 레지스터 (16비트, 6개)
메모리를 세그먼트 단위로 분할하여 관리할 때 각 영역의 시작 주소(또는 Selector)를 보관합니다.

* **CS (Code Segment)**: 실행할 기계어 명령어가 위치한 영역
* **DS (Data Segment)**: 변수 및 데이터가 위치한 영역
* **SS (Stack Segment)**: 런타임 스택 영역
* **ES, FS, GS**: 추가적인 데이터 세그먼트 (FS/GS는 Thread Local Storage, OS 전용 데이터 등에 활용)

---

#### ③ 상태 및 제어 레지스터 (2개)

* **EIP (Instruction Pointer, 32비트)**
  * CPU가 **다음에 실행할 명령어의 메모리 주소**를 보관합니다.
  * 명령어가 실행됨에 따라 자동으로 증가하며, `JMP`, `CALL`, `RET` 등의 명령어로 변경됩니다.
* **EFLAGS (Status Flags, 32비트)**
  * CPU 연산 결과의 상태를 표시하거나 CPU 동작을 제어합니다.
  * **주요 상태 플래그**:
    * `CF (Carry Flag)`: 부호 없는 정수 연산 시 캐리/보로우 발생 여부
    * `OF (Overflow Flag)`: 부호 있는 정수 연산 시 오버플로우 발생 여부
    * `ZF (Zero Flag)`: 연산 결과가 $0$ 인지 여부
    * `SF (Sign Flag)`: 연산 결과가 음수인지 여부 (MSB가 1)
    * `PF (Parity Flag)`: 연산 결과 1의 개수가 짝수인지 여부

---

### 2. 64비트 (x86-64) 범용 레지스터 확장 (16개)

64비트 모드로 진입하면 **범용 레지스터가 8개에서 16개로 확충**되며, 크기도 64비트(`R` 접두사)로 확장됩니다.

* **기존 확장 레지스터 (8개)**: `RAX`, `RBX`, `RCX`, `RDX`, `RSI`, `RDI`, `RBP`, `RSP`
* **신규 추가 레지스터 (8개)**: `R8`, `R9`, `R10`, `R11`, `R12`, `R13`, `R14`, `R15`

#### 64비트 레지스터 서브 파트 접근 방식
| 64비트 | 32비트 | 16비트 | 8비트 (Low) |
| :--- | :--- | :--- | :--- |
| **RAX** | EAX | AX | AL |
| **RBX ~ RSP** | EBX ~ ESP | BX ~ SP | BL ~ SPL |
| **R8 ~ R15** | **R8D ~ R15D** | **R8W ~ R15W** | **R8L ~ R15L** |
